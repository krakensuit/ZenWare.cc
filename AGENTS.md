# AGENTS.md — ZenWare.cc

Чит для Left 4 Dead 2 (Source, 2009): internal-DLL + GUI-лоадер + external-оверлей. Только обучение и локальный сервер с `-insecure`.

## 1. Контекст проекта и стек

- C++17 (`stdcpp17`), MSBuild v143, SDK `10.0.26100.0`, **только `Release | Win32`**, `/MT`, `/utf-8`, W3. Тестов нет.
- `ZenWare.sln` = 3 проекта (DLL + Loader + External). `Tools/SigScan` — отдельный `.vcxproj`, **не** в солюшене.
- Локально MSBuild есть (BuildTools 2022), но гейт — CI (`build.yml`: msbuild + проверка, что лоадер ≥2 МБ, без выгрузки артефактов).

```powershell
powershell -ExecutionPolicy Bypass -File Build-SingleFile.ps1  # всё + dist\ZenWare.exe
.\Verify-Signatures.bat              # 0 = паттерны ок, 2 = чинить Offsets.cpp
```

### Карта (неочевидное)

- `ZenWare.DLL/src/Entry/Entry.cpp` — порядок инициализации: лог → паттерны → интерфейсы → хуки. `DllMain.cpp` — только `CreateThread`, логики нет.
- `ZenWare.DLL/src/Features/Vars.h` — ВСЕ настройки (inline-глобалы по namespace). `Config/` — `key=value` (`aimbot.fov`), слот конфига сессионный.
- `ZenWare.DLL/src/Features/Menu/` — своё immediate-меню 320x480, табы Visuals/Move/View/Combat/Misc (`case N:` в `Render()`), скролл/клиппинг есть. Подпись виджета = EN-строка, перевод — в `Lang.h`.
- `ZenWare.DLL/src/Features/*/` — фичи: `Run/OnTick` из CreateMove, `Draw/Render` из Paint.
- `ZenWare.DLL/src/Util/Offsets|Pattern/` — 15 сигнатур; `ZenWare.DLL.vcxproj` — **единственное** место регистрации новых `.cpp/.h` (иначе LNK только на CI).
- `ZenWare.DLL/external/` — MinHook (не трогать) + subset FontAwesome (UTF-8).
- `ZenWare.Loader/resource.h` — `ZENWARE_VER_STR`, единственное место версии. Сетевого кода нет (апдейтер удалён).
- `l4d2_base.sln/.vcxproj/.filters` под `src/` — мёртвое наследие v142, не собирать.
- `XorString _()` — заглушка (`#define _(x) x`). Source-only: билды только в git-ignored `dist/`, никогда в git/релизы/CI.

## 2. Автоматические правила использования инструментов

- `context7` — при ЛЮБОМ вопросе про библиотеки и API: STL, Boost, Win32 API, MSVC, версии пакетов. Даже если ответ кажется известным. НЕ использовать для движка Source, оффсетов и сигнатур — там только местный реверс.
- `memory` — перед ответом проверять, что уже известно; автоматически сохранять долгоживущее: структуры бинарников, найденные уязвимости, архитектурные решения, грабли («первое совпадение паттерна бьёт мимо»). НЕ сохранять: адреса под конкретный билд, логи, статусы задач.
- `sequential-thinking` — обязательно для сложных задач: архитектура, дебаг вылетов, реверс-инжиниринг, правки ≥3 файлов, новая механика аима/движения. Для мелочей не нужен.
- `filesystem` — чтение файлов ВНЕ корня проекта: заголовки SDK, либы, DLL игры (`<Steam>\...\Left 4 Dead 2\left4dead2\bin\` — только чтение, писать туда запрещено).
- `bash` — только терминал: сборка, компиляторы, `dumpbin`, `gh`, git. НЕ использовать для чтения/поиска/правок файлов — для этого read/glob/grep/edit.
- `websearch` — CVE, эксплойты, информация новее знаний модели. НЕ использовать для документации библиотек (это context7).
- `question` — перед стартом сложной или неоднозначной задачи задать 3–5 уточняющих вопросов (объём, направление, допуски). По мелочам не дёргать.
- `task`-субагенты — параллельный разбор независимых подсистем, только отчёты с `file:line`, без правок.
- Сначала читать файлы самому (read/glob/grep). Диагностика вылета: `<gamedir>\left4dead2\ZenWare.log`, строки `[!!!] EXCEPTION` и `[!!!] last breadcrumb`.

## 3. Правила работы с C++

- Табы, Allman, `.editorconfig` + `.clang-format`; русский в комментах ок.
- Стиль: короткие функции, ранний `return`, без глубокой вложенности; магические числа — в именованные константы.
- Ошибки — fail-closed: отсутствующий паттерн/интерфейс/указатель = ранний `return`/`false`, никаких исключений через границы детуров. Образец — таблица `aNeed` + abort в `Entry.cpp`, `Init(nullptr) → false` в `Hook.h`.
- Указатели: объекты движка — сырые невладеющие указатели + проверка `nullptr` и `GetClientClass()->m_ClassID` перед виртуалкой/нетваром (падали на таблетках: ветка `CWeaponSpawn`-only обязательна). Своя память — `std::unique_ptr`/RAII, голого `new/delete` избегать.
- Только netvars, не виртуалки (`GetEyePosition()` = `m_vecOrigin()+m_vecViewOffset()`).
- Ивентов движка нет by design (`Killfeed::OnTick` — опрос, не `IGameEventManager`).
- `float`-слайдеру нужен int-прокси + синхронизация в `Render()` и ресинк в `Load config`.
- Рисование только через `G::Draw`, строки формата — литералы (`L"%ls"`), `wsprintfW` запрещён. `trace_t`/`player_info_t` всегда `= {}`. STL ок, блокировок в детурах нет, фон — короткие detached-треды.
- После правок C++: `git push` → дождаться CI success → пересобрать `dist\ZenWare.exe`, если пользователь его запускает.

## 4. Правила реверс-инжиниринга

- Паттерны IDA-стиля, скан только `.text`; адрес = match ± константа — **та же арифметика обязана совпасть в `Tools/SigScan/Main.cpp`** (`m_nAdjust`).
- DLL хранит абсолютные адреса, SigScan печатает `base+RVA`, кэш — RVA + fingerprint DLL. Чинить только `NOT FOUND`/`AMBIGUOUS` (первое совпадение бьёт мимо молча — так было с `CheckForSequenceChange`, он выключен в `Hooks.cpp`).
- Каждую находку документировать: адрес/RVA, смещение, размер, сигнатура, причина («почему это оно»), затронутые `file:line`.
- Уязвимости и краш-грабли — с оценкой серьёзности (CVSS-подобно: вектор, влияние на стабильность/детект), важное сохранять в `memory`.
- Находки — короткий `//` с причиной + строка в `CHANGELOG.md` (Unreleased, EN+RU).
- Чужой код и бинарники в репозиторий не нести (только механика своими словами); `*.dll` — gitignored.

## 5. Правило планирования

- Перед написанием кода или анализом бинарника ВСЕГДА составлять план из 3–5 шагов через sequential-thinking: что читаем → гипотеза → проверка → правка → верификация.
- План фиксировать в todowrite, крупные задачи бить на шаги, статусы обновлять по ходу работы.
